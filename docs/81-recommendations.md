# Recomendaciones

- **Sobre el Roadmap y Siguientes Sprints:** Tras finalizar el desarrollo de la Single Page Application (Frontend) en el Sprint 2, se recomienda que el equipo concentre sus esfuerzos en la construcción del Backend y la integración de las APIs reales en el Sprint 3. Es fundamental asegurar una arquitectura robusta para la base de datos y la implementación definitiva del Identity & Tenant Context, garantizando así la correcta seguridad y segregación de datos por policlínico (Multi-tenant).

- **Validación Temprana y Usabilidad (Testing):** Ahora que se cuenta con la aplicación web funcional (Frontend) desplegada en Firebase, se recomienda fuertemente organizar rondas de pruebas de usabilidad (Validation Interviews) con los médicos y recepcionistas abordados en el Capítulo II. Recolectar feedback sobre la navegación, los flujos de agendamiento y el diseño visual permitirá realizar ajustes valiosos antes de la etapa de integración final.

- **Integraciones de Terceros (APIs):** De cara a la madurez del producto, se recomienda ir analizando la documentación técnica de sistemas de terceros para los módulos secundarios, específicamente la API de RENIEC (para el registro rápido de pacientes y validación de identidad) y las pasarelas de facturación electrónica validadas por SUNAT.

- **Gestión Documental:** Se sugiere al equipo mantener el rigor en el flujo de Docs-as-Code y los Conventional Commits en el repositorio de GitHub, ya que la trazabilidad del código y la documentación integrada facilitarán enormemente la auditoría del proyecto en las entregas finales.
